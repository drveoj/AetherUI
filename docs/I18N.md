# Translating AetherUI

Nothing is translated yet. Everything is *translatable*, which is a different
and more useful thing to have finished: the words are out of the code, the
packager knows how to put translations back in, and the day somebody offers to
translate it there is nothing to build first.

## The shape of it

| | |
|---|---|
| `Core/Locale.lua` | the phrase table, `A.L`, and `A.F` for phrases with holes in them |
| `Locale/enUS.lua` | the English. **Edited by hand** — this is where you fix wording |
| `Locale/deDE.lua` … | one per language, each nothing but an `@localization@` block |
| `Tools/i18n.py` | finds strings that ought to be phrases and are not |
| `Tools/rekey.py` | names new phrases and files their English |
| `.pkgmeta` | what goes in the zip |
| `.github/workflows/release.yml` | builds the zip on a `v*` tag |

## A key names the phrase; it is not the phrase

```lua
desc = note(A.F(L.options.minimap.desc, A.Bad(L.common.in_combat))),
```

The first version used the English itself as the key, which is the CurseForge
convention and is **wrong for a project still being written**: correcting a typo
in a sentence changes its key, and every translation of it already submitted is
orphaned by the fix. It also puts two hundred characters of prose in the middle
of a line of code.

So a key is a name, and it comes from where the phrase lives rather than from
what it says — the file gives the area, the enclosing function the group, the
table key on the line the leaf:

```
Core/Options.lua                       -> options
  local function MinimapGroup()        -> minimap
    ring = toggle("Border", nil, ...)  -> ring.name
                                          options.minimap.ring.name
```

That is stable against every edit to the words themselves, which is the point.

A phrase used in more than one place is one phrase, under `common.*` — `on`,
`off`, `Take the tour`. A translator renders it once, and two lines of the same
readout cannot disagree with each other.

**Reading is nested, storage is flat.** `L.options.minimap.desc` reads as what
it is; underneath there is one table keyed `"options.minimap.desc"`, because
that is the shape the packager writes.

## Two layers

The player's language sits on English. A phrase nobody has translated yet draws
correct English, so a half-translated language is half translated rather than
half blank — which is why `enUS.lua` ships in every zip and is not merely the
import file.

A key in **neither** draws its own path — `options.minimap.desc` on screen. That
is loud on purpose: it is a coding mistake rather than a translation gap, and it
should look like one.

## Correcting the English

Edit `Locale/enUS.lua`. It is **not generated** — that is the whole point of
naming the keys. Reword freely; no key moves, so no translation is disturbed.

## A sentence with a hole in it

```lua
A:Print(A.F(L.cmd.skin.skin_s, name))      -- "skin -> %s"
A:Print(L.cmd.skin.skin_prefix .. name)    -- no
```

The format string is the phrase, so a translator gets the whole sentence with
its placeholder still movable — which is most of what translating a sentence
*is*. Handed a prefix they have half a sentence and no idea what follows it.

`A.F` is `string.format` with a seatbelt: a translation carrying `%d` where the
English had `%s` throws, and these arrive from volunteers on a website rather
than through review here, so the failure lands on the phrase and the format
string draws instead.

## What is not translatable, on purpose

- **Anything the client says.** Spell names, zone names, item names, class
  names. They already arrive in the player's language; putting them through this
  would be translating a translation.
- **The changelog.** Release notes, rewritten every version. Asking volunteers
  to translate a paragraph that will be replaced on Tuesday is how a translation
  project dies.
- **Media, Palette.** Texture paths, font files, colour token names.

## Adding a phrase

By hand, which is two lines:

```lua
-- Locale/enUS.lua
L["toolbox.rail.tooltip"] = "Drag to move the rail"

-- wherever it is drawn
b:SetTooltip(L.toolbox.rail.tooltip)
```

The suite fails on a key the source asks for and `enUS.lua` has not got, and on
an entry in `enUS.lua` that nothing asks for.

## Sweeping for phrases somebody left bare

```
python Tools/i18n.py --report        what is still a bare string, by file
python Tools/i18n.py --report Core/Chat.lua    ... and what each one is
python Tools/i18n.py --wrap          wrap the ones it is sure of
python Tools/rekey.py --dry          what it would call them
python Tools/rekey.py                name them and file the English
luajit Tools/harness.lua             and the suite has to be green
```

Two tools because they answer different questions. `i18n.py` asks "is this a
phrase?", which is decidable from the **call site** — a string handed to
`SetText` is read by somebody, a string handed to `GetModule` is not. `rekey.py`
asks "what is it called?", which is decidable from where it lives.

The report has three columns. **left** is what a wrap would take; **by hand** is
a sentence with an expression concatenated into it, which wants `A.F` and which
the tool will not guess at; **done** is what is already going through `L`.

A site `i18n.py` does not recognise is reported rather than guessed at — a wrong
guess is a frame name run through a translation table, which is a `nil` at some
distance from the mistake.

`rekey.py` never overwrites an entry already in `enUS.lua`. That file is edited
by hand and a tool that rewrote it from scratch would throw away every
correction in it.

## Turning it on

1. Create the project's phrase list on CurseForge and paste `Locale/enUS.lua`
   into the phrase importer — once. (Header lines excluded; the importer wants
   the `L["…"] = "…"` lines.)
2. Add a `CF_API_KEY` secret to the repository.
3. Tag a release. The packager replaces each `@localization@` block with
   whatever CurseForge holds at that moment.

Until step 2 the release workflow builds the zip and attaches it to the GitHub
release and uploads nothing anywhere.

**Translations do not live in this repository.** A `deDE.lua` with German in it
would be overwritten by the next package. They live on CurseForge, and they
arrive in a release through the substitution block.
